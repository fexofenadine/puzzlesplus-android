# Architecture notes

How Puzzles Plus is put together, written for whoever works on it next. It grew a section at a time and
is dense: **a code review pass should make it readable** (see `docs/handover/code-review-pass.md`).

Eight games (Minesweeper, Takuzu, Nonograms, Sudoku, 2048, Light Up, Futoshiki and Bridges) share one
shell (`src/shell/`) that provides the window, taskbar, themes, backgrounds, zoom, pause, resume,
records and the guides. Each game is a folder in `src/` with the same shape: `rules.js`, `solver.js`,
`techniques.js`, `generate.js`, `hint.js`, `app.jsx` (state and actions), `Game.jsx`, `Cell.jsx`, `Menu.jsx`.

## Layout and each game

Files that exist upstream stay flat in `src/` where upstream has them (Button, Dialog, Overlay, Input, Digit, Menu, app.css...) and double as shared primitives. Our own code shared between games lives in `src/shell/`; game code stays out of it. A second game (Takuzu, planned) gets its own folder and page.

- `src/shell/actions.js` `shellState(page)` and `shellActions` (theme, menus, zoom/fit/maximise, window state, background settings, boss key, portrait) spread into a game's state and actions, `listen(actions)` for auto-pause and orientation, `shortcut(event, state, actions)` for the typing/modifier/Esc rules, + and - zoom, and nothing while the window is hidden. Games must provide `pause(paused)`, `press(event)` and `reset()`. `windowState` is open, minimised (`minimise` pauses, the taskbar button restores, still paused) or closed (`close` resets the game and sets `openGames` to the page; `openGame(id)` navigates to another game or shows this one again with the fresh game)
- `src/shell/Taskbar.jsx` the Windows 95 taskbar on every game and theme: Start (the user's GitHub avatar, bundled as `shell/avatar.png`) with a menu of games, How to Play, About and GitHub; a button per game (`taskbarGame` minimises the open one, restores, or navigates); a tray with the boss key and a clock that updates its own text. Fixed at the bottom, `--taskbar` (28px plus safe area) is main's bottom padding, which `measureFit` subtracts, and `Overlay` leaves it uncovered. Icons in `shell/icons/` are the favicons' 32px frames. `src/shell/OpenGames.jsx` the dialog Close opens (arrows, Enter, Esc or Cancel brings the window back), linking `../how-to-play/`. `src/shell/DisplayMenu.jsx` Zoom In, Zoom Out, Actual Size, Maximise (picked over title bar zoom buttons so Beginner keeps its width), the Theme and Motion flyouts and the rest of the display options (was ViewMenu and ThemeMenu until 2026-11-19)
- `src/shell/About.jsx` the shared About box (credits and licence paragraph, repo link) each game's `About.jsx` fills with its own paragraphs, so the licence summary lives in one place. `src/shell/Board.jsx` `PausedCover` and `HintPanel` (with `hangBelow`), `Board.module.css` also holds `.outline`, the hint outline both games' cell styles `composes`. `src/shell/Tabs.jsx` the best times tab row. `src/shell/clock.js` `pauseAction(running, onPause)` builds both games' pause. `src/shell/prepaint.js` the theme and zoom pre-paint script, inlined into each page's `<!--prepaint-->` by the `prepaint` plugin in `vite.config.js`
- `src/shell/SideButton.jsx` the small scoreboard button beside the face (with `HintIcon`, `UndoIcon`), used by Takuzu's undo and hint and by Minesweeper's hint, which is left out on classic. Minesweeper centres the face and hint as a pair (`.buttons`) so beginner's narrow scoreboard stays balanced
- `src/shell/records.js` `records(prefix, sizes, levelNames)` gives `timeKey`, `eachSlot` and the winner/best times actions (`win`, `submitBestTime`, `toggleBestTime`...) for Takuzu and Nonograms, keyed `<prefix>.<n>.<level>[.hints]` plus `.name` and `<prefix>.name`; `src/shell/BestTimes.jsx` their size by level grid (`allowed` shows a dash); `src/shell/Prompt.jsx` the full-board yes/no question with a game's own title and text; `src/shell/rain.js` `showRain(on)` draws ｼ and ﾓ (the user's pick) with `glyphImage` from `matrix.js` as `--rain-0/1` and sets `data-rain` on the root
- `src/shell/HowToPlay.jsx` the Help → How to Play box (shared shortcuts paragraph last), each game's own `HowToPlay.jsx` gives the rules; `howTo` and `toggleHowTo` live in the shell state and actions. `src/shell/GameLinks.jsx` `gameLinks(current)` lists every game at the bottom of each Game menu, the open one checked
- `src/guide/` the guide pages: `Guide.jsx` `startGuide({ page, root, home, title, icon, parts })` builds a page app (shell state and actions, Theme menu, taskbar with its own window button, boss key; Esc is its only key, so the games' saved zoom stays put) with a help-viewer window of contents beside an article, `parts` being `[{ title, sections: [{ id, title, body() }] }]`; the section the hash names is marked `data-current` from script (Firefox misses `:target` on late drawn sections). `minesweeper.jsx`, `takuzu.jsx`, `nonograms.jsx` hold each guide (How to Play, Beginner, Advanced) and `howToPlay.jsx` the shared short page; `desktop.jsx` the window and themes section all three share; `pages/*.js` are the entries for `<game>/guide/index.html` and `how-to-play/index.html`. Examples (`MinesExample`, `TakuzuExample`, `NonogramsExample`) are real positions found by searching dealt boards, drawn with the games' own cells, captioned by the games' own hint or technique text; `guide.test.jsx` fails if an example stops producing its technique. Each game's `HowToPlay.jsx` exports `Rules` for the dialog and the pages, and each `hint.js` has `guideTopic(hint)`, the section id a hint's More button (`HintPanel`'s `more`) opens in a new tab
- `src/shell/icon.py` draws the Puzzles Plus icon (Nord since 2026-11-02, no white: Frost blue #5e81ac piece, light Frost #88c0d0 plus, slate #4c566a background, bevels mixed from each fill toward Snow Storm and Polar Night; centred on the piece's smallest enclosing circle, which the user found balanced in round masks where centring by bounding box or centre of mass sat it low and left; the plus's arms stop 10px short of the notches' bevels; the plus bevelled as mitred polygon strips, the piece's bevel shaded by distance to its nearest edge, both because mask-shifting left stray pixels in the corners) into `public/icon.png`, `icon-512.png`, `favicon.ico`, `docs/puzzlesplus.png` (README title) and `docs/social-preview.png` (upload by hand in the repo's settings, GitHub has no API for it); `--android <res>` also writes the app's launcher icons and splashes. Only the root and How to Play pages use it, the games and guides keep their own icons
- `src/shell/WindowControls.jsx` title bar pause, minimise and maximise/restore (`windowProps` fills them), the Dialog's `onClose` adds close and `hidden` hides the window, the Display menu (uses the `MenuItem`/`SubMenuItem`/`Separator` exported from `Menu.jsx`)
- `Overlay.jsx` `guardClicks` ignores pointer clicks until a press starts inside the dialog: cells act on pointerdown, so the tap that won opened the name box and its click then hit OK (Firefox Android, 2026-10-30). Keyboard clicks (detail 0) still count
- `src/app.jsx` state, actions and view root. Hyperapp 1 actions are `(payload) => (state, actions) => partialState`
- `src/mines.js` mine placement (`placeMines`) and the logic solver (`solvable`) behind No Guessing
- `src/hint.js` `findHint`, pure function over the visible board that returns `{ kind, cells, sources, text }`
- `src/Game.jsx`, `Cell.jsx`, `Menu.jsx`, `BestTime.jsx`, `Winner.jsx` views, each with a `.module.css`
- `src/shell/backgrounds/` animated xscreensaver ports behind the game. `index.js` is the host (one canvas, one rAF loop, theme to background map, settings store), `matrix.js` (GLMatrix), `substrate.js` (Substrate), `truchet.js` (Truchet) and `phosphor.js` (Phosphor, with `font6x10.js` generated from xscreensaver's 6x10font.png) each export `{ name, credit, options, ratio(dpr), filter?(dpr), wallpaper?, create(context, settings) }` where create returns `{ configure, resize(w, h, scale), frame, still? }`. A new xscreensaver port is one file plus one line in `backgrounds` and `themeBackgrounds`
- `src/shell/backgrounds/driftclouds.js` classic's opt-in animated background (replaced the hill on 2026-11-16 at the user's word): drift's 2D Clouds shader (`driftclouds.glsl`, from xscreensaver 6.17, the author allows any use, credit wanted), like Neon through `shader.js` `shaderBackground(meta, source)`, which also holds `adapt` and the web's frame rate check (`frameRate`: frames after the first second, median of 20 gaps, under 10 fps gives up for the photo; the app never checks). Resolution defaults differ by build through `shell/platform.js` `app`: 100% in the app, 50% (clouds) and 65% (neon) on the web
- `src/shell/BackgroundSettings.jsx` builds its controls from a background's `options` (range, toggle, select), so new backgrounds need no UI code
- `src/shell/Boss.jsx` the boss key spreadsheet (`makeSheet` random figures kept in `state.boss` so rerenders don't reshuffle), opened from the taskbar tray too. It sets `data-boss` on the root, which the background host watches to stop drawing
- `src/shell/zoom.js` zoom steps, fit maths and the game window watcher used by the `fit` and `zoom` actions
- `src/shell/themes.js` the theme list (id, menu name) shared by the Theme menu and saved-theme validation
- `src/shell/storage.js` localStorage wrapper that survives blocked storage, always use it instead of `localStorage`
- `src/app.css` themes are `:root[data-theme=...]` variable sets, fonts live in `src/fonts` (all freely licensed)
- Pages: root `index.html` only redirects to `minesweeper/` (old links), `minesweeper/index.html`, `takuzu/index.html` and `nonograms/index.html` are the games, `<game>/guide/index.html` their guides and `how-to-play/index.html` the short rules of all three, all inputs in `vite.config.js`. `shellState(page, root)` takes the way back to the site's top (`../` for games, `../../` for guides). `build/` maps one to one onto `/puzzlesplus/` on github.io and `\\nidhogg\web\puzzles\`, with one shared `assets/` folder. Per-game icons, manifest and link preview live in `public/<game>/`
- `src/takuzu/` Takuzu. UI: `app.jsx` (state, actions; cell clicks are `play`, `press` is the keyboard; Ctrl+Z undo is the one modified shortcut), `Game.jsx` (window, scoreboard with empties left, undo, face, hint, clock), `Cell.jsx` (theme colour tokens `--tz-zero`, `--tz-one` and their text colours live in `Cell.module.css`, not app.css; Solarized uses cyan and magenta, the user's pick after finding blue and orange out of place; all digits bold, clues framed), `Menu.jsx` (Game, Size, Theme; `allowed(n, level)` rules out expert 6x6, falling back to hard), best times through `records('takuzu', ...)`, the full-board question (shell `Prompt`, asked at once when the last click left the cell at the end of its cycle, 1 for left clicks or 0 for right clicks, otherwise after 2.5 s via `ask(change)` unless the board changed, so stepping through 0 to reach 1 never triggers it), `deal.js` deals in `deal.worker.js` (falls back to the page without Worker or when the worker errors, stale deals dropped by id). Saved keys `takuzu.size`, `takuzu.level`, `takuzu.errors`, `takuzu.name`. Core: `rules.js` (boards are `Int8Array` n*n of -1/0/1, lines 0..n-1 rows then columns as bitmasks, `linesOf(n)` every valid line, `violations`, `solved`), `solver.js` (exact line-candidate solver with branching, `countSolutions`, `solve`; not used for hints), `generate.js` (seeded `random`, `makeSolution` (restarts the random search after `4n` steps: without that, 1 seed in ~2000 took from seconds to over a minute), `makePuzzle` removes clues while `keep` holds, default exactly one solution; `makeGame(n, level, rng, budget)` keeps boards the techniques up to `level` finish and that need exactly that level, 1.5 s budget then the hardest found). `techniques.js` the human ladder, each technique returns steps `{ technique, level, place, sources, text }`: easy pair, gap; medium count; tricky one-left, twins (added 2026-10-29 because hard was a cliff after medium; `upgradeLadder` cleared old best times once and moved a saved hard or expert choice up, flagged by `takuzu.ladder` = 5); hard balance, repeat; expert what-if. Levels 0-3 together equal the solver's line propagation (tested), so what-if trials use `propagate`. `nextSteps`, `rate(givens, n, top)` gives the hardest level needed or null. `hint.js` `findHint({ board, solution, n })`: broken rule, then a cell that doesn't fit the solution, then the easiest step; marks map cells to source/zero/one/wrong; `completeWithErrors` is the full-board prompt. Deal times: 14x14 expert median ~0.6 s, worst ~1.3 s, 12x12 occasionally ~1.5 s at any level (slow random solutions), the rest well under 0.3 s. 6x6 has no expert by the user's choice, though it can deal one
- `src/nonograms/` Nonograms Plus (complete 2026-10-30, plan in memory). Phase 4: best times through `records('nonograms', ...)`; the full-board prompt when `fillsLeft` (rules.js) hits 0 unsolved, at once unless the stroke was a single mouse click from empty to fill (that may be on its way to a cross), then after 2.5 s via `ask(change)`; Rain Glyphs (`nonograms.rain`) draw fills as ﾓ on black. `techniques.js` the ladder: easy (complete: clue 0, a clue that fills the line exactly, a line with all its runs; overlap and gap from each run pushed both ways counting only crosses, `pushed`), medium (forcing and reach, the same counting fills too), hard (line: anything `settleLine` proves), expert (what-if via `contradiction`, which names the line that broke). `lineSteps(values, clue, level)` gives one line's steps with `text(name, ends)`; `settleUpTo(level)` feeds `propagate` so `solveAt(board, n, clues, level)` and `rate(clues, n, top)` grade boards; each level finds everything below it. `makePuzzle(n, rng, top, deadline)` repairs pictures until `solveAt(top)` finishes (easy pictures 12% denser), `makeGame(n, level, rng, budget)` wants exactly `level` (1.5 s, 3 s from 20x20, then the hardest found, else a quick medium board). Worst deals ~1.6 s; hard boards take ~0.3 s median since most line-solvable pictures are already medium. 5x5 never needs expert, so `allowed` in `Menu.jsx` greys it out. `hint.js` `findHint({ board, solution, clues, n })`: broken line (only cells that differ from the solution red), a misfit cell, then the easiest step, with `line` for the clue outline; ghosts show the placed fill or cross. Saved `nonograms.level`. `rules.js` boards of -1 empty, 0 cross, 1 fill; clues are run lengths, rows then columns; `settleLine(values, clue)` is the dynamic-programming line solver (before/after tables, time ~ cells x runs, checked against brute force) behind everything; `lineDone`, `solved` (crosses never needed), `breaks` (lines that can't match, with `line`). `solver.js` `propagate` (queue of lines, optional start lines), `deduce(board, n, clues, deep)` returns 0 line logic, 1 what-if, null stuck; `countSolutions`. `generate.js` `makePicture` (density 0.48-0.56 noise, two majority smoothing passes from 10x10 up, mirrored half the time), `makePuzzle` flips an unsettled cell until logic finishes (4n flips then a new picture) and only tries what-if once lines leave a quarter or less open (without that one 25x25 seed took 50 s; now worst ~0.9 s, median ~12 ms). `app.jsx` strokes: `down` starts one (cycle empty, fill, cross; touch taps use `mode`), window pointermove finds the cell by `data-cell` and calls `drag`, which locks to the first axis moved along and paints cells that had the start cell's old value; `up` commits it as one undo step of `[cell, from]` pairs. `Game.jsx` clues and cells share grid tracks (`tracks(n)`, 2px gap every 5, cells placed with `place(k)`), done clues dim, broken ones red under Show Errors, scoreboard counts fills left. Touch screens get a fill/cross mode button. Saved keys `nonograms.size`, `nonograms.level`, `nonograms.errors`, `nonograms.rain`, `nonograms.name`, `nonograms.procedural` and `nonograms.symmetric` ('off' when off, both default on), `nonograms.solved`. Pictures (2026-11-10): `art.js` loads `art/<size>/<name>.txt` (header `name`/`credit`/`licence`/`source`, `---`, then # and . rows) with `import.meta.glob`, `parseArt` throws naming the file, `pickArt(n, level, rng, id, avoid)` picks the level or nearest; `art.test.js` fails on a bad, unsolvable or wrong-sized file. `filled(cells, n)` (generate.js) is the rule for drawn and art pictures: every edge touched, no empty line up to 10x10. Symmetric is the default for drawn boards (flips keep the mirror); off deals non-symmetric ones. With Procedural off, `dealing.js` (page and worker) deals from the pool; Choose Picture (`Pictures.jsx`) shows solved thumbnails only and a picked game (`game.picked`) keeps no time; random art times go on the Art tab (`records(..., true)`, keys `nonograms.art.<n>.<level>`, no hints), and a won picture shows name and credit under the board. All pictures are original CC0 (single credit line), not found art
- `src/sudoku/` Sudoku Plus (built 2026-11-08, plan in memory `sudoku-plan`). `rules.js` boards Int8Array of 0 empty and 1..n, candidates Int32Array bitmasks (bit d-1); `boxShapes` maps size to box width x height and `sizes` is just [9] for now (another size is one entry, `geometry(n, layout)` builds units, `unitsOf`, `peers`, unit names like "the top left box"; a variant adds units there). Jigsaw (2026-11-21, the first variant, 9x9 only): a `layout` is a string of 81 region digits passed as the last argument of `geometry`, `candidatesOf`, `breaks`, `solved`, `settle`, `countSolutions`, `solve`, every technique, `nextSteps`, `apply`, `rate` and `findHint`; its regions are units of kind `box` named by their first cell ("the region from row 2, column 3"), `geometry(...).word` says box or region. `generate.js` `makeLayout(rng)` walks the usual boxes by handing a cell to a neighbouring region and another back while all regions stay connected, `makeGame(n, level, rng, budget, regions)` deals a layout of its own per attempt (returned as `layout`). `game.jigsaw` and `game.layout`, saved key `sudoku.variant`, saved games and links carry the layout (a fourth `.` part), best times are the size `jigsaw` (`sizeName` in shell/grid.js). Region edges are `regions.js` `regionEdges` as `--et`/`--el` box shadows read by `SudokuCell.module.css` `.region`; the Game menu's Jigsaw Regions item and the guide's Variants section (`jigsawExample`) hold the rest `solver.js` `settle` (naked and hidden singles to a fixpoint, false on contradiction), bitmask search with the narrowest cell first: `countSolutions`, `solve`. `techniques.js` steps `{ technique, level, place, remove: [[cell, mask]], sources, text }`: easy hidden and naked singles; medium pointing/claiming (`lockedCandidates`), naked and hidden pairs; hard triples, quads, X-Wing, XY-Wing; expert Swordfish, XYZ-Wing, Jellyfish, what-if (singles from a supposed digit). `rate` uses `settle` for the singles (much faster than step objects). `generate.js` removes clues in 180° symmetric pairs, keeping `minGivens` (36/30/25/20 of 81); expert keeps only uniqueness while removing and rates once at the end (what-if finishes nearly anything); worst deal ~0.7 s. `hint.js` repeats, wrong digit, notes missing the answer, then the next placement; if removals come first it applies them silently and explains the one that opened the placement (`enabler`), text "(removal). Then (placement)"; quads and jellyfish share their triples' and swordfish's guide sections. UI: selection is a cell or a picked digit (`selected`, `picked`), pad digits go into an editable selected cell else pick; taps with a digit picked place it (right click a note); `noting` (Space or the pad's Notes button), Shift+digit notes, arrows, Backspace/Delete/0 erase; `tidy` (Tidy Notes, `sudoku.tidy`) clears peers' notes as part of the same undo step (`edit` builds steps of [cell, digit, notes]); Auto Notes. Styles live in `Sudoku.module.css` and `SudokuCell.module.css` because class names are scoped by file name only, and `Game_inactive` etc. clashed with `src/Game.module.css` on the guide page. Board tracks are 1px lines and 2px between boxes (`tracks`, `place`), 32px cells, pad digits share the tracks. `icon.py` draws its icons. Guide examples (`guide/sudoku.jsx`) are positions found by searching dealt boards, with `removed` candidates; the test checks each is the easiest step there
- `src/2048/` 2048 Plus (built 2026-11-08, plan in memory `2048-plan`; id and folder `2048`, the taskbar imports its icon as `twenty48` since a name can't start with a digit). `rules.js` `slide(values, n, dir)` on plain values (for the search) and `move(tiles, n, dir, nextId)` on tiles `{ id, value, cell, fresh, merged, gone }` with the same result (tested), so tiles keep their element and slide by CSS transform; merge halves stay as `gone` until the next move under the new `merged` tile; `targets` is 512 on 3x3 (2048 can't fit), else 2048. `search.js` two-move expectimax (chance nodes sample up to 6 cells) over a heuristic (free cells, monotone lines, smoothness, biggest tile in a corner), `suggest` gives `{ dir, text }` with reasons; following it reaches 1024+ on 4x4 (tested). `app.jsx` arrows/WASD, drags on the board (`swipeStart`/`swipeMove`/`swipeEnd`, rules in `drag.js`): the direction locks after 10px and never changes, tiles follow the finger scaled to the furthest one (`planOf`, `offsetsOf`), the release finishes once the finger is more than 10px onwards like the original, else (brought back near the start) they spring back; a stuck direction only nudges. Slides are Web Animations on `translate` from each Tile's `onupdate` (`glide`, 100 ms), not css transitions, because hyperapp re-inserts keyed tiles when last move's merge halves go, which cancelled transitions; halves hide 0.3 s after a merge; new tiles grow and merges pop 0.2 s after a 0.1 s delay, the original's timings, unlimited undo of `{ values, score }` (a save keeps the last 100), Keep Going prompt once (shell `Prompt`), game over offers a best score, and so does leaving a game for a new one. `records.js` best score plus highest tile per size, `2048.<n>[.help]` with `.tile`, `.name`; tabs No help / Hints or undo (`BestScores.jsx`); Winner takes an optional `text`. Timer is off by default (`2048.timer` = 'on'). Tiles in `Board2048.module.css` (2026-11-08, user's picks): the original's rounded tray, slots and tiles (gap 14% of a cell, glow on 128-2048) on every theme; a theme palette `--t-c1..11` with text `--t-text`/`--t-f1..11` where set (Classic the original's colours, Solarized its accents ending in gold, Synthwave indigo to pink to neon yellow), else the hue ramp (`--t-hue`, `--t-step`, `--t-turns`, `--t-l0`, `--t-ld`, text by lightness against `--t-mid`; Nord, Matrix), `--t-top` past 2048. Clear Sans bold (`src/fonts/clear-sans-bold.woff`, Apache 2.0, from the original repo) on Classic, Nord and Solarized at the original's sizes (`--t-s2..5`); Matrix and Synthwave keep their fonts. `--t-drop` centres each font's digits, measured from their ink (Courier Prime sits 0.07em high). Tile motion lives in `motion.js`: drags set `style.translate` on the elements (`hold`, `letGo`) without rendering, and `glide` starts from the tile's on-screen offset so chained moves and releases never jump. A restored save must still have a move (a stuck one came back paused forever). Guide `guide/2048.jsx`: strategy examples captioned by `suggest`, the test holds each to its move
- `src/lightup/` Light Up Plus (built 2026-11-15, the sixth game; id and folder `lightup`, title "Light Up" on classic). `rules.js` a layout is Int8Array n*n of WHITE -1, a wall numbered 0 to 4 or BLANK 5; a board is the player's marks EMPTY -1, CROSS 0 (a note: no bulb here, never needed to win), BULB 1; `sightsOf(layout, n)` (cached per layout) the white cells in line with each cell up to a wall, `besideOf(n)`, `litOf`, `darkLeft` (the scoreboard), `breaks` (bulbs lighting each other, a wall with too many bulbs or too little room), `solved`; sizes 7, 10, 14. `solver.js` `settle(layout, n, board, why)` runs the plain rules in place (a full wall crosses, a wall needing every free cell fills, a dark cell with one place to be lit from gets its bulb), false on a break with `why.wall` or `why.dark`; `countSolutions`, `solve` branch on the dark cell with the fewest places. `techniques.js` steps `{ technique, level, place: [[cell, BULB|CROSS]], sources, text }` with `text` a getter so grading never builds sentences: easy need, full, boxed; medium lone (the only cell that can light another); hard squeeze (a bulb that would light too many free cells beside a wall) and starve (one that would light every cell a dark cell could be lit from); expert what-if through `settle`. `rate(layout, n, top)`. `generate.js` walls on about a fifth of the board, the same turned half round, a greedy random set of bulbs, every wall numbered, then numbers blanked while `keep` holds (rating below expert; expert keeps one solution and rates at the end); 14x14 deals take ~0.1 s median, 0.2 s worst, every level exact. `hint.js` broken rule, a wrong mark (a bulb the solution lacks or a cross on one of its bulbs), then the easiest step that places a bulb: cross-only steps are applied quietly and the ones in the bulb step's scope come with it (`place` and marks include them, the first one's reason leads the text). `app.jsx` is Takuzu's shape (`place`, `play`, `move`, `type`: Space steps, B bulb, X cross, Backspace clears); the all-lit-but-wrong prompt waits 2.5 s after a clicked bulb (it may be on its way to a cross), at once when typed. Styles in `LightUp.module.css` and `LightUpCell.module.css` (unique file names, see Sudoku); tokens `--lu-wall`, `--lu-wall-text`, `--lu-light`, `--lu-bulb` default to the theme's dark shadow, title text and smiley colour. Daily 10x10 medium, links pack the layout base 7, saved keys `lightup.size`, `lightup.level`, `lightup.errors`, `lightup.timer`, `lightup.name`, `lightup.saved`. `icon.py` draws its icons; guide `guide/lightup.jsx` with `LightUpExample.jsx` (rows of . o x # and digits), examples found by searching dealt boards, the test holds each to being the easiest step. - `src/futoshiki/` Futoshiki Plus (built 2026-11-16, the seventh game). A puzzle is `{ n, givens, right, down }`: boards Int8Array of 0 empty and 1 to n, `right[i]` and `down[i]` the sign between a cell and its neighbour (NONE, LESS: the cell is the smaller, MORE); the game object is itself a puzzle, so `solved(board, game)`, `breaks`, `violations`, `countSolutions(puzzle)`, `solve`, `rate(puzzle, top)` and `findHint({ board, solution, puzzle })` all take it. `rules.js` `geometry(n)` rows and columns as units, `pairsOf(puzzle)` every sign as [small, big] (cached per pair of sign boards: caching on `right` alone gave stale lists when only `down` changed and made the dealer keep boards with several answers), bit helpers from sudoku's rules, sizes 4 to 7, `allowed` (no 4x4 hard, pairs there are too rare). `solver.js` `tighten(masks, puzzle)` (signs bound each other's candidates, a settled cell clears its lines, a digit with one place goes there) and a search on the narrowest cell; the test checks counts against a plain brute force. `techniques.js` steps with `place` and `remove` like Sudoku's, text as a getter: easy naked and hidden singles, beside (a sign next to a placed digit), ends (chains of signs); medium limits (between two empty cells); hard naked and hidden pairs; expert what-if through `tighten`. `generate.js` a shuffled cyclic latin square with every sign, then digits and signs taken away in one shuffled order while `keep` holds (taking digits first left boards of signs only); worst deal ~0.8 s (4x4 and 5x5 hard), 7x7 under 0.2 s. `hint.js` as Sudoku's without the notes check: removals go quietly and the one that opened the placement (`enabler`) is explained first. UI reuses Sudoku's `Cell`, `Pad` (now exported, with `columns`) and `lookOf`; `Game.jsx` `tracks`, `place`, `Signs` (one glyph, turned a quarter for signs between rows), cells 32px with 15px gaps on `Futoshiki.module.css`. `app.jsx` is Sudoku's with the signs added to createGame, pack and unpack, links (each cell `digit * 9 + right * 3 + down` in base `(n + 1) * 9`). Daily 6x6 medium. Guide `guide/futoshiki.jsx`, `FutoshikiExample.jsx` (`{ rows, right, down }` as strings; `exampleStep` lets easier removals go quietly and fails if a digit can be placed first)
- `src/bridges/` Bridges Plus (Hashi, built 2026-11-21, the eighth game; id and folder `bridges`, title "Bridges" on classic). `rules.js` a puzzle is `islands`, Int8Array n*n of 0 water or the island's number (1-8); `linksOf(islands, n)` (cached per array) lists the links between islands next to each other in a row or column (`{ a, b, across, cells, max }`, max the smaller number or 2) with `at` (links of an island), `over` (links that would cross) and `through` (links over a water cell); a board is the bridges on each link (0 to 2) in that order, so saved boards are only good for the same islands. `breaks`, `solved` (degrees, no crossing, one group), `unfinished` (the scoreboard), `stepLink` (0, 1, 2; null where a bridge crosses). `solver.js` a state is `{ lo, hi }` per link, `settle` (degrees add up, a bridge shuts the ones across it, a finished group must be everything) and a search (`countSolutions(islands, n, limit, steps)` treats running out of steps as more than one answer, so a crafted link can't hang the page). `techniques.js` steps `{ technique, level, change: [[link, lo, hi]], sources, text }` with `text` a getter built from numbers captured when the step was made: easy need, full, crossed; medium limit; hard isolate (more bridges would close a group), exit (a group's only way out); expert what-if. `hint.js` as Light Up's: broken rule, a link with more bridges than the solution, then the easiest step that raises a link (steps that only rule links out go quietly and come with it as `none` marks); marks are `{ cells, links }`. `generate.js` `makeIslands` grows a tree of bridges (never two islands side by side) then adds bridges between neighbours; `makeGame` keeps boards with one answer at exactly the level (7x7 expert ~1% of boards, still ~0.1 s). UI: click an island then another in line (`selected`), or drag (`drag`, `up` finds the island under the pointer by `data-cell`), or click the water (the link with a bridge, else the hint's, else the first); right click steps back; arrows hop to the next island, Shift+arrow builds. Cells are divs, bridges are background gradients (`BridgesCell.module.css`); `Game.jsx` `drawings`. Daily 10x10 medium, links pack the islands base 9, saved keys `bridges.size`, `bridges.level`, `bridges.errors`, `bridges.timer`, `bridges.name`, `bridges.saved`. `icon.py` draws its icons; guide `guide/bridges.jsx` with `BridgesExample.jsx` (rows of digits with - = | : for bridges), examples found by searching dealt boards

## Behaviour worth knowing

- Mines are placed on the first click that actually opens a cell, not on a flag or chord. Placing on a flag broke No Guessing (fixed in 6e9df2e)
- No Guessing clears the first click and its neighbours, then redeals until `solvable` passes (1.5 s budget, falls back to an unchecked board). Expert needs ~20 tries, ~20 ms
- Hint (Game menu or `H`) uses only visible numbers and the player's flags, never the real mines, so a wrong flag can mislead it. Rules in order: contradicting flags, satisfied number or all-mines number, subset pair, mine counter, otherwise "needs a guess"
- Asking for a hint after the first click sets `game.hinted`. Best times are stored separately: `beginner`/`beginnerName` for no hints, `beginnerHints`/`beginnerHintsName` for hints used. The best times dialog has a tab for each and Reset Scores clears the open tab only
- The hint and chord explanation panel stays until the board changes (cells opened, a flag placed, a new game), not on every mouse down: clearing it on the first click of a double click resized the centred window and moved the board, so the second click hit another cell. Since then the panel (both games) also hangs below the window's place: `hangBelow` in `shell/zoom.js` gives the window's wrapper a negative bottom margin equal to the panel and `measureFit` leaves it out, so neither centring nor fit moves the board when a hint comes or goes; a window that fills the screen lets the panel run past the bottom and the page scrolls. `findHint` returns `marks` (index to source/safe/mine/wrong) so `Game.jsx` needs no extra logic
- A failed chord (double-click, both buttons or Shift, or a tap on touch screens) shows `explainChord` in the hint panel. `game.openedAt` stops the double-click that just opened a number from counting as a failed chord on it
- Levels: beginner, intermediate, expert and extreme (39x21, 169 mines, expert density grown 30% each way). Custom is limited to 40x30
- Zoom replaced the corner resize grip: View → Zoom In/Out (or + and -) step through `steps` (0.5 to 4), title double-click or Actual Size is 100%. Maximise (`zoom.maximised`, saved as `maximised`) uses `maxZoom(fit)`, the largest scale the room allows in 0.01 steps, not below `MIN_FIT`, refitting on resize; any zoom step leaves it. `zoom.chosen` is what the player picked (saved as `scale`), `zoom.scale` is what is shown. The `fit` action shrinks to fit the browser but not below `MIN_FIT` (0.625), where the page scrolls. It runs from a ResizeObserver on the game window and on browser resize, and ignores the window's own zoom changes (`sameSize`, 3% tolerance, since borders make the unzoomed size drift ~1% between zooms), so zooming in past the fit stays and scrolls
- Portrait screens (`state.portrait`, from a matchMedia orientation listener) show a board that is wider than tall transposed (`transposed` in Game.jsx). Only the view changes: cells keep their own x and y, and hint directions swap via `findHint`'s `transposed`
- The window title is `Minesweeper` on classic and `Minesweeper Plus` on every other theme (Game.jsx). Help → About (`About.jsx`, `toggleAbout`) has the blurb, credits and repo link; keep its licence summary in step with the README credits
- Pause (title bar button before −, `P`) only works while a game runs (after the first open, before win or loss). Resume shifts `game.start` by the paused time. While `game.paused` the cell actions and hint do nothing and Game.jsx draws every cell as an unopened tile. Hiding the tab or blurring the window pauses, nothing ever resumes on its own
- Esc is the boss key (`boss` action, also the taskbar tray's Esc button and the spreadsheet's 100% status text for touch screens). While it shows, every other shortcut is ignored. `Overlay` stops Esc propagating so closing a dialog with Esc never triggers it
- Keyboard shortcuts (F2, N, H, P, Esc) are ignored when the target is an input or a modifier key is held; Takuzu's Ctrl+Z undo is the exception. Esc closes an open menu before it shows the spreadsheet
- Rain Glyphs (Theme menu, matrix only, `takuzu.rain` and `nonograms.rain`) use the shell `rain.js`: Takuzu shows ｼ for 0 and ﾓ for 1, Nonograms ﾓ for fills. The shared `ThemeMenu` renders a game's own items passed as children
- The matrix rain builds its glyph atlas lazily on its first frame
- Classic maps to the `driftclouds` background with `animated: false`, so by default classic keeps the original photo and look; the pre-paint script in each game's index.html skips `data-background='animated'` on classic to avoid a flash
- Every background gets a shared `animated` option from `optionsOf` (default from the background's `animated`, else true). Off means `data-background` is `wallpaper` (the theme's css wallpaper, solarized themes keep their code photo) when the background sets `wallpaper: true`, otherwise `still` (substrate fast-forwards ~3000 cycles into an ImageData buffer then stops). Matrix's wallpaper is `src/matrix.webp` (WebP since 2026-11-08, as are synthwave and solarized), a CC0 Markus Spiske digital rain photo. The css hides a solarized wallpaper only under `data-background='animated'`
- Truchet defaults differ from xscreensaver's (scroll on, slow 1px steps, solarized accents at 45% strength) so it stays calm behind the game. Phosphor types the game's own source (lazy `import.meta.glob` raw chunks of everything under `/src`) and adds a Brightness option (20%, lowered from 55% on 2026-11-01) for the same reason
- The `solarized` theme id is Solarized Truchet, kept so saved choices still work
- Substrate's Detail option sets its canvas ratio: balanced (default, up to 1.5x), sharp (full dpr, slow on big hidpi screens) or original (1x). Its cycles scale linearly with that ratio, not by area, which made 1440p at 2x take ~21 ms a frame
- Canvases draw at the display pixel ratio (substrate per its Detail option, matrix up to 2x with its 0.6 screen pixel blur scaled by 1/dpr) and resize on browser zoom or a screen change via a resolution media query
- All background settings are saved together under the `backgrounds` key, cleaned against each option's range or choices on load. The dialog edits a draft that previews live, OK saves, Cancel restores. Matrix defaults are the original tuned look (44 strips, speed 1, matrix glyphs, fog and waves on); substrate defaults are xscreensaver's own
- Substrate is a function-for-function port of substrate.c; canvas source-over with globalAlpha is the same blend as its trans_point, so there is no offscreen buffer
